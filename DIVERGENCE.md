# DIVERGENCE.md

Mangarr is a fork of Sonarr v5. This document enumerates every intentional divergence from `Sonarr/Sonarr` `v5-develop`, with rationale.

Format: flat table grouped by subsystem. Updated by hand when divergences land or move from "planned" to "merged." This is a **static inventory**. The original Phase 0 framing deferred the upstream-sync cadence schedule + CI divergence-flag job per CONTEXT.md D-17 "may be reopened in a future milestone"; that framing is **SUPERSEDED** by Phase 21 D-13/D-14 (closed 2026-05-16) — **Mangarr is a permanent hard fork as of v1.0.0**: upstream sync ENDS at v1.0.0 (D-13), and `v5-develop` is kept only as a read-only mirror for blame/reference (D-14). The Whisparr-style quarterly-sync cadence is therefore NOT reopening; this document remains a static historical inventory. See [.planning/phases/00-pre-code-decisions/00-CONTEXT.md](./.planning/phases/00-pre-code-decisions/00-CONTEXT.md) `<deferred>` section (original framing) and [.planning/phases/21-distribution-v1-release/21-CONTEXT.md](./.planning/phases/21-distribution-v1-release/21-CONTEXT.md) D-13/D-14 (permanent-hard-fork superseder).

Type taxonomy: `extend`, `replace`, `delete`, `new`, `preserve`.

Sonarr does NOT auto-seed indexers, download clients, or notifications — users opt in

|----------|---------------|------|----------------|

**Where the seed lives:** `IndexerFactory.InitializeProviders()` +
`DownloadClientFactory.InitializeProviders()` overrides — the same canonical
`IHandle<ApplicationStartedEvent>` -> `InitializeProviders()` extension point that
`MetadataSourceFactory` already uses to seed MangaDex as the default primary
metadata source. Inherits `ProviderFactory<TProvider, TProviderDefinition>`'s base
`Handle(ApplicationStartedEvent)` which calls `InitializeProviders()` after
`RemoveMissingImplementations()`.

**Idempotency:** `if (All().Any()) return;` short-circuit (the S4 pattern from
`TranslationProfileService.Handle(ApplicationStartedEvent)`). A user who deletes a
seeded row will NOT see it recreated on the next start — the user-override-respect
contract is sacred. The seed only fires when the entire table is empty, not "if my
specific seeded row is missing".

**Rationale:** PROJECT.md design philosophy locks in *"preserve Sonarr's shape
wherever it works; diverge only where the manga domain forces us"*. The v1 UX lock
forces this divergence: without seeded providers, `/settings/downloadclients` and
`/settings/indexers` are empty on a fresh DB and the user has no signal which
Implementation to pick from the long list in the Add modal. The bundled in-process
downloader has zero external dependencies, so seeding it is risk-free; MangaDex is
the BEDROCK metadata source already (Phase 3 D-19) so seeding the matching indexer
keeps the source slate aligned end-to-end. Comix is the reference port #1 (Phase 3
plan 03-05) — seeding it gives the user a second source out of the box for
diversification.

### Addendum 2026-05-22 — captureToken pattern adopted

**Trigger:** comix.to deployed a bundle rotation between 2026-05-12 and 2026-05-22 that moved the signer function out of `globalThis.<namespace>.<fn>` shape entirely. Concurrently, upstream keiyoushi recognized that namespace-walking is unsustainable and switched to a structurally simpler design: **don't probe — observe**. Upstream commit `965dc242` (2026-05-12, "Comix: only get token via webview") deletes `Signer.kt` entirely and pivots `Comix.kt` to a `captureToken()` shape. The Phase 17 architecture (process-singleton runtime signer that probes `globalThis.vmf_*` for behaviour-matching signer + installer fns) is upstream-obsolete. See `.planning/debug/comix-signer-rotation.md` for the full root-cause + decision record.

**Architecture pivot (replaces the Phase 17 PROBE_JS shape):**
- Drop PROBE_JS namespace walk + Phase 17.2 D-1 networkidle settle + in-IIFE BRANCH-C decrypt routing in the signer JS template + all `SignerExpr` / `InstallerExpr` cached state + `EvaluateRawAsync` diagnostic seam.
- Replace with PuppeteerSharp request-interception: `page.SetRequestInterceptionAsync(true)` + `page.Request += handler` capture the `?_=<token>` query parameter off the page's OWN outgoing API request.
- Two routes mirroring upstream `Comix.kt`: `/manga/{hid}/chapters` → load `/title/{hid}` (match `/api/v1/manga/{hid}/chapters`); `/chapters/{chapterId}` → load `/chapters/{chapterId}` (match `/api/v1/chapters/{chapterId}`).
- After token capture, relay the API GET server-side via `System.Net.Http.HttpClient` (Choice B per debug doc — `client.newCall(GET(url, headers)).awaitSuccess()` analog) — preserves the existing `IComixSigner.ProxyFetchAsync(apiPath) → Task<string>` contract perfectly. PR #244 review feedback (Codex P1 + CodeRabbit Major) refined this further: the relay reuses a process-singleton `_relayHttpClient` (not per-call `new HttpClient()`), forwards browser session state onto the relay (cookies via `_page.GetCookiesAsync(comix.to)` + UA via `navigator.userAgent` cached at warm-time), and calls `EnsureSuccessStatusCode()` so non-2xx flows through to lazy-reprobe + `RecordFailure` instead of silently degrading.
- Mangarr-only optimization: per-`pageUrl` token cache with 5-minute TTL so pagination loops reuse a single capture (upstream Android re-captures per request because WebView spin-up is cheap; PuppeteerSharp page loads are 3-8s, worth caching).
- `WaitUntil = DOMContentLoaded` (not `Networkidle0`) — the bundle's long-lived sockets defeat network-idle. Bounded by `CaptureTimeoutSeconds = 30` (mirrors upstream `Comix.kt:466 latch.await(30, SECONDS)`). ## Phase 22 — TagInUseValidator (Mangarr-only enhancement)

Wiring constrained by Pattern B (`src/Mangarr.Http/REST/RestController.cs` exposes only `PostValidator` / `PutValidator` / `SharedValidator` — no `DeleteValidator` property, no DELETE branch in `OnActionExecuting`); the explicit pre-check in the action body is the only available wiring without a cross-cutting base-class change. ### Considered and rejected as divergences

The v1.1 milestone deliberately considered and rejected two patterns as divergences from Sonarr-canonical shape. They are recorded here so future planners do not relitigate them.

- **OAuth token encryption-at-rest** — Sonarr-canonical **plaintext storage** at-rest per Phase 27 D-01..D-04. Mangarr's 3 ImportList provider plugin POCOs mirror Sonarr Trakt `TraktSettings.cs:27-37` verbatim: `[FieldDefinition(... Hidden = HiddenType.Hidden)]` on `AccessToken` / `RefreshToken` / `Expires` / `AuthUser` (the canonical pattern is the `Hidden = HiddenType.Hidden` field-definition attribute, NOT an application-layer encryption envelope). **NO `EncryptedSettings` BLOB column.** **NO DPAPI.** The threat model is identical to Sonarr's: defense-in-depth via OS file permissions on the SQLite DB at `<datadir>/mangarr.db`, not application-layer encryption. GH #216 (filed at Phase 27 close-out requesting at-rest encryption) was closed wontfix per Phase 27 D-03 — accepting this divergence would force a Mangarr-only secret-management substrate that has no upstream peer, breaks the PROJECT.md design philosophy ("preserve Mangarr's shape wherever it works; diverge only where the manga domain forces us"), and provides marginal security benefit over OS-level filesystem permissions for a single-user self-hosted *arr application. See `.planning/reference/sonarr-vertical-slices/notifications-extra/Trakt/TraktSettings.cs:27-37` for the canonical Sonarr POCO shape Mangarr's plugins mirror.

- **Per-ImportList `SemaphoreSlim` for OAuth token refresh** — **correctness fix, NOT a divergence** per Phase 27 D-05. The pattern mirrors Sonarr Trakt's `RefreshTokenIfNecessary()` lazy-refresh shape at `.planning/reference/sonarr-vertical-slices/notifications-extra/Trakt/Trakt.cs:127-153` verbatim: reactive-on-401 (5-minute expiry-window lookahead + retry-on-401 force-expire) with a per-`Definition.Id` keyed `SemaphoreSlim` to serialize concurrent refresh attempts (preventing the read-modify-write race when `ImportListSync` + a manual Test trigger both hit a near-expiry token within milliseconds of each other and would otherwise both attempt to consume the single-use `refresh_token`, producing a `400 invalid_grant`).
